# PR本文テンプレート（このリポジトリ共通）

このリポジトリでPRを作成するときは、本文に以下の項目を必ず含めること。

## 必須項目

1. **原因**: なぜ問題が起きるのか（仕様・実装上の理由。新機能の場合はなぜ必要になったか）
2. **修正方法**: どう直したか（採用したアプローチとその理由）
3. **制御フロー**: 分岐・ガード処理（ログイン済みかどうか、成功/失敗など）がある場合、処理の流れをフローチャート風の簡易図で示す
4. **該当箇所**: 修正したファイル・関数・行
5. **簡易な比較図**: 修正前/修正後の違いが一目でわかる簡易図式（ASCIIツリーやコード片の並記など）
6. **テスト**: 実際に何を確認したか（コマンド・手順・結果）
7. **補足**: レビュワーに伝えておきたいこと・次にやるべきこと・既知の制約など（無ければ「特になし」と書く）

## テンプレート

```markdown
## 概要
<1行で何を直したか>

## 原因
<なぜ問題が起きるか（新機能の場合はなぜ必要になったか）>

## 修正方法
<どう直したか、なぜその方法にしたか>

## 制御フロー
<分岐・ガード処理がある場合のみ記載。無ければこの節ごと省略してよい>
```
処理の入口
    │
    ▼
  条件？
 ── ┴ ──
Yes     No
 │       │
 ▼       ▼
処理A   処理B
```

## 該当箇所
- `path/to/file.ts` の `funcName`（行番号）
- ...

## 修正前/修正後
```
修正前                 修正後
<簡易図式>             <簡易図式>
```

## テスト
<確認した手順・コマンドと結果>

## 補足
<無ければ「特になし」>
```

## 注意
- ハッカソンリポジトリのルールにより、**PRのマージは行わない**（責任者がマージする）。
- 変更はコンフリクトを避けるため最小限・影響範囲を最小限にとどめる。
- 制御フローの図は、単純な1〜2行の修正など分岐が無いPRでは省略してよい。
